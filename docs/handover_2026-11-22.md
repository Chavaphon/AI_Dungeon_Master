## 9. Environment gotchas

- Always send `num_ctx` from `config/model.json` (8192). With no `num_ctx`, Ollama loads at 16384, spills 16% to the CPU and generates about ten times slower (`docs/hardware.md` §4).
- Every run starts from a freshly loaded model, and nothing else uses the Ollama server during it (`docs/model_selection.md` §3, CLAUDE.md §15 item 25).
- Send no `format` field (no JSON mode) on any request (CLAUDE.md §15 item 26).
- Never write the model name anywhere except `config/model.json`. `tests/test_model_config.py` fails if it appears in `adm/`.
- Serve with the standalone `C:\Users\USER\ollama-0.35.1\ollama.exe serve`, not the tray app: the tray app updates itself, and the client refuses any version but 0.35.1. Nothing else may listen on port 11434.
- The first model load after a reboot takes about 35 s; later cold loads take about 7 s.
- In PowerShell, activate the venv with `.venv\Scripts\Activate.ps1`; if `python` opens the Microsoft Store, call `.venv\Scripts\python.exe` directly. In Git Bash, `source .venv/Scripts/activate`.
- Demo and Sponsor User play always passes `--runs` with a folder outside `runs/` (CLAUDE.md §14, `docs/live_demo.md`).
- The working copy is often left on a feature branch. Check `git status` before running anything that depends on `main`.
- `docs/defence/deck.pptx` is edited in PowerPoint (or, for notes, in its XML). After any change, update its sha256 in `docs/defence_deck.md` §6.
